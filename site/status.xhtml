Cloudflare Pages — recommended

Deploy on Cloudflare in ~60 seconds

Cloudflare renders plain .html (no .xhtml tricks), serves the site from its global edge, and — unlike jsDelivr — needs no cache purging: every push triggers an atomic redeploy with pages and chat data together. The repo ships a wrangler.toml, so the import configures itself:

  1. Go to dash.cloudflare.com → Workers & Pages → Create → Pages tab
  2. Connect to Git → pick ok5678765s/veil-os → Begin setup
  3. Leave everything as-is (wrangler.toml sets output dir site, no build command) → Save and Deploy

That's it. Your *.pages.dev link updates itself: the backup daemon pushes every 30s when chat data changes → Cloudflare redeploys automatically. Fastest, lag-free mirror there is.

Got "error occurred while running deploy command"? That was a name-match bug in the config (fixed now — the project name can be anything). Just push Retry deployment on the failed build, or delete the project and import it again. Make sure you're on the Pages tab — not the default Workers one — when importing.

Vercel deployment

Vercel link showing a broken chat? 60-second fix.

If your Vercel project says "not signed in", shows an empty member list and a register form that does nothing, it imported the whole Next.js app — Vercel can't run Veil's database or chat server, so that version can never work. Point it at the static site/ mirror instead:

  1. In Vercel, open your project → Settings → General
  2. Framework Preset → Other · Build Command → leave empty · Output Directory → site
  3. Save, then Deployments → newest → the ⋯ menu → Redeploy

The repo now ships a vercel.json with these exact settings, so any new Vercel project you import from ok5678765s/veil-os configures itself automatically — no settings needed.

Remember: the Vercel link is the read-only mirror. Sign-up, sending and the live member list only exist in the real Veil app (the sandbox preview panel) — nothing hosted on static files can change that.
